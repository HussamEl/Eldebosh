# النشر: غيتهب يبني، والاستضافة تسحب

> **الحالة `2026-09-03`:** الربط قائم والموقع يسحب فعلاً — الدليل أنّ ختم البناء
> بجانب زر الهوم ظهر في النسخة الحية. الباقي المحتمل: الـWebhook (القسم «ثالثًا»).
> إن كان مضبوطًا فالسحب تلقائي بلا لمسة؛ وإن لم يكن، فالسحب يدوي بأربع نقرات
> (القسم التالي).

---

## ما معنى «اسحب من hPanel»؟

جملةٌ كرّرتها كثيرًا دون أن أشرحها. معناها **أربع نقرات في لوحة الاستضافة**،
لا أكثر — ولا علاقة لها بجهازك ولا ببرنامج تنزّله:

```
hPanel  ←  Websites  ←  eldebosh.com  ←  Dashboard
        ←  Advanced  ←  Git  ←  تبويب Overview  ←  زر Redeploy
```

**لماذا تُطلب أصلًا:** غيتهب لا يستطيع الدخول إلى الاستضافة (المنفذ محجوب —
الجدول أعلاه). فالاستضافة هي التي تخرج وتأخذ نسخة الموقع من فرع `deploy`. زر
`Redeploy` هو الأمر الذي يقول لها: **اخرجي وخذي الآن**.

**ومتى لا تُطلب منك أبدًا:** إن كان الـWebhook مضبوطًا (القسم «ثالثًا» أدناه)،
فغيتهب يطرق باب الاستضافة بعد كل بناء ناجح، وهي تسحب وحدها. عندئذٍ لا تفتح
hPanel إطلاقًا.

**وكيف تعرف أيّهما وضعك:** بعد أي تعديل أرفعه، انظر إلى **ختم البناء بجانب زر
الهوم** على الموقع. تغيّر وحده خلال دقائق ← الـWebhook يعمل، انسَ هذا القسم.
بقي قديمًا ← الـWebhook غير مضبوط، فإمّا تضبطه مرة واحدة، وإمّا تضغط `Redeploy`
بعد كل تعديل.

---

## لماذا هذا يعمل بينما FTP لم يعمل

| | FTP من GitHub Actions | هذا المسار |
|---|---|---|
| اتجاه الاتصال | GitHub **يدفع** إلى الاستضافة | الاستضافة **تسحب** من GitHub |
| من يفتح الاتصال | خادم GitHub — **وهو المحجوب** | خادم الاستضافة نفسه |
| النتيجة | `Timeout (control socket)` بعد دقيقتين | لا منفذ خارج ليُحجب |

الحجب كان على اتجاه واحد فقط: الدخول إلى الاستضافة. والخروج منها إلى غيتهب مفتوح
— وهو ما تستخدمه ميزة Git المدمجة في hPanel.

**والاستضافة لا تتغيّر.** تبقى على Hostinger.

## البنية

```
main     المصدر كله + site/     ← أدفع أنا هنا
  ↓      GitHub Actions: يبني ويفحص
deploy   محتويات site/ في الجذر  ← تسحب الاستضافة من هنا
  ↓
public_html
```

فرع `deploy` يحمل الموقع المبني وحده: `index.html` و`.htaccess` و`sv/` و`en/`
في الجذر مباشرة — تمامًا كما تريده الاستضافة.

**والتاريخ خطّي دائمًا:** كل نشر commit ابن لسابقه، فلا يفشل السحب أبدًا.

## الإعداد — مرة واحدة

> الخطوات مُتحقَّق منها من توثيق Hostinger في أغسطس 2026. الأسماء قد تختلف قليلًا
> إن حُدِّثت الواجهة — المعنى هو الثابت.

### أولًا: نظّف قبل أن تبدأ

**احذف كل محتويات `public_html` من File Manager.** سببان: Git لا ينسخ إلى مجلد
فيه ملفات غريبة، والرفع فوق القديم يترك صفحات لم تعد تُولَّد وهي تعمل. هذه المرة
الوحيدة التي ستحتاج فيها التنظيف.

### ثانيًا: اربط المستودع

**١.** `hPanel` ← `Websites` ← موقعك ← `Dashboard`

**٢.** من القائمة الجانبية: `Advanced` ← `Git`

**٣.** اضغط `Continue with GitHub` — سيطلب تسجيل الدخول إلى غيتهب وتثبيت تطبيق
Hostinger. اختر مستودع `Eldebosh` وحده، لا كل المستودعات.

**٤.** اختر المستودع من القائمة ثم `Next`، واملأ:

```
Branch:          deploy          ← ليس main
Root directory:  public_html
```

> ⚠️ **الفرع `deploy` لا `main`.** الفرق أن `main` يحمل المصدر كله — لو نشرته
> لظهر `src/` و`node_modules` وملفات المشروع على الإنترنت. أما `deploy` فيحمل
> الموقع المبني وحده في الجذر.

**٥.** اضغط `Deploy`. السجل يظهر مباشرة أثناء التنفيذ.

**٦.** افتح `eldebosh.com` — يجب أن يظهر الموقع.

### ثالثًا: فعّل النشر التلقائي

في صفحة Git ستجد نافذة تحمل **عنوان Webhook** — انسخه، ثم:

```
https://github.com/HussamEl/Eldebosh/settings/hooks
```

`Add webhook` ← الصق العنوان في `Payload URL` ← `Content type: application/json`
← `Just the push event` ← `Add webhook`.

**تمّ.** من الآن: أدفع إلى `main` ← Actions يبني ويفحص ← يحدّث `deploy` ←
الـWebhook يوقظ الاستضافة ← تسحب. بلا لمسة منك.

### إن لم تجد Git في القائمة

الميزة غير متاحة في كل الخطط. إن لم تظهر تحت `Advanced`، فالبديل: نزّل فرع
`deploy` كـZIP من غيتهب وارفع محتوياته — لا بناء ولا `npm`، الملفات جاهزة.

---

## ⚠️ قبل أول سحب: نظّف `public_html`

الاستضافة ستضع الموقع في مجلد فيه ملفات قديمة. احذف **كل** محتوياته أولًا من
File Manager — وإلا بقيت صفحات لم تعد تُولَّد وهي تعمل بتصميمها القديم. (تكرر
هذا ثلاث مرات في هذا المشروع.)

بعد أول سحب ناجح، لن تحتاج تنظيفًا مجددًا: Git يحذف ما حُذف من المستودع.

---

## كيف تتأكد أن النشر جرى

**١. على غيتهب:** بطاقة خضراء بجانب آخر commit في `main`، ثم افتح فرع `deploy`
وانظر تاريخ آخر تعديل.

**٢. على الموقع:** افتح المصدر (`Ctrl+U`) وابحث عن:

```
<meta name="eldebosh-build" content="...">
```

هذا وقت البناء. إن كان قديمًا، فالسحب لم يجرِ.

## إن تعطّل شيء

| العرض | الأرجح | الفحص |
|---|---|---|
| Actions أحمر | فشل فحص، فلم يُنشر شيء | افتح السجل على غيتهب — الفحص الفاشل مسمّى |
| Actions أخضر والموقع قديم | الـWebhook لم يصل | اسحب يدويًا من hPanel بزر `Deploy` |
| الموقع بلا تنسيق | `.htaccess` لم يصل أو مجلد خاطئ | تأكد أن `Directory` هو `public_html` |
| صفحة محذوفة ما زالت تعمل | بقايا ما قبل أول سحب | نظّف `public_html` وأعد السحب |

**السحب اليدوي متاح دائمًا:** صفحة Git ← تبويب `Overview` ← زر `Redeploy`.
وهذا خط الرجعة إن تعطّلت الأتمتة — لا يحتاج جهازك ولا بناءً محليًا.

**وتبويب `Deployments`** يعرض تاريخ كل نشر: الفرع، ورقم الـcommit، والوقت،
والحالة. اضغط أي سطر لترى سجله كاملًا. هذا أول مكان تنظر فيه عند أي شك.

## والرفع اليدوي؟

يبقى صالحًا كخطة بديلة: نزّل فرع `deploy` كـZIP وارفع محتوياته. الإجراء الكامل
في [05-deployment.md](05-deployment.md).

الفرق أن `deploy` **جاهز للرفع كما هو** — لا بناء، ولا `npm`، ولا جهاز.
