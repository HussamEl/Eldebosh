# Architecture

How eldebosh.com is built, and why it is built that way. For the rules the
code enforces, see [RULES.md](RULES.md); for running and publishing it, see
[OPERATIONS.md](OPERATIONS.md).

---

## In one paragraph

A static site generated by **Astro 5** from YAML and MDX files in `src/`. Every
push to `main` is built and checked by **GitHub Actions**; if every check
passes, the built site is committed to the **`deploy` branch**, and
**Hostinger** pulls that branch into `public_html`. The owner edits content in
**Sveltia CMS** at `/admin/`, which commits to `main` like any other push. No
server code, no database, no secrets.

```
 owner in /admin/ ─┐
                   ├─► main ──► GitHub Actions: build + all checks ──► deploy ──► Hostinger pulls ──► eldebosh.com
 developer push ───┘                   │ (fails → nothing is published)
```

---

## Why these choices

| Choice | Reason |
|---|---|
| Static output | Fastest pages on a phone, nothing to hack, cheap hosting. The content changes a few times a day at most |
| Astro content collections | Every page and product is a typed record (zod schema in `src/content.config.ts`); a malformed file fails the build instead of rendering wrongly |
| Products as YAML data, not pages | One product appears in guides, comparisons and solutions; its facts live in one file, so they cannot disagree between pages |
| Build in CI, not locally | The admin panel commits source only. If the built site were committed by hand, admin edits would never reach visitors |
| Host pulls, CI does not push | Hostinger blocks inbound connections from GitHub (FTP from Actions timed out). Its built-in Git deploy pulls outbound instead, triggered by a webhook |
| Reproducible builds | The version stamp is the last source commit's time, not the build time. The same source builds to identical files, so a docs-only push publishes nothing |
| One stylesheet, local fonts | One request for all CSS; no third-party font requests (privacy, GDPR, speed) |
| Almost no JavaScript | Speed and robustness. The only script enhances two things that also work without it |
| Sveltia CMS shipped from `node_modules` | Pinned version, no CDN dependency, and the test suite tests the exact file that is served |

## Repository map

  i18n/ui.ts            every interface string in sv and en, URL segments, reserved paths
  styles/global.css     all styles, one file, design tokens on :root

## Content model

### Collections

| Collection | Files | Key fields |
|---|---|---|
| `products` | `src/data/products/sv/*.yaml` | `code` (P-NN, permanent), `category`, `subcategory`, `key_specs`, `price_band`, `owned`, `tested`, `own_photos`, `asin`, `source_url`, `verified` |
| `categories` | `src/data/categories/*.yaml` | `id`, `active`, names and slugs per language, `subcategories` |
| `solutions` | MDX | `problem_id`, `question`, `symptoms`, `icon`, `featured`, `products` |
| `guides` | MDX | `solution`, `picks` (product + badge + reason) |
| `comparisons` | MDX | `solution`, `products` (2–4), `verdict` |
| `posts` | MDX | `solution` |
| `pages` | MDX | fixed legal and about pages |
| `torget` | YAML | stall contact block |

Every page has `lang`, `slug`, `title` (≤ 70 chars), `description` (50–165),
`category`, `published`, `stage`, `updated`, optional `sources`.

### Two independent switches

- **`published`** — is the URL live?
- **`stage`** — how far is the text? `draft` → `written` → `reviewed` → `published`.

A live page with stage `draft` or `written` is a **skeleton**: the template
replaces its body with a "not written yet" notice (`NotWritten.astro`), adds
`noindex`, and shows no products. See [RULES.md §2.6](RULES.md#26-no-thin-content--a-skeleton-is-a-promise-with-a-date).

### Product visibility

A product is shown only if `verified: true`. The chain a reader follows:

```
solution page (problem)  ◄── guide / comparison / article (solution: <problem_id>)
         │                              │
         └── products ──────────────────┴── picks / products ──► product YAML ──► buy link from asin
```

## URL structure

Built by `url` in `src/lib/content.ts`; segments in `SEGMENTS` in
`src/i18n/ui.ts`. **Changing either after publication breaks search rankings
— owner's decision only.**

| Page | Swedish | English |
|---|---|---|
| Home | `/sv/` | `/en/` |
| Category | `/sv/laddning-och-strom/` | `/en/charging-and-power/` |
| Subcategory | `/sv/laddning-och-strom/powerbanks/` | `/en/charging-and-power/power-banks/` |
| Solution | `/sv/solutions/<slug>/` | `/en/solutions/<slug>/` |
| Guide | `/sv/guides/<slug>/` | `/en/guides/<slug>/` |
| Comparison | `/sv/compare/<slug>/` | `/en/compare/<slug>/` |
| Article | `/sv/blog/<slug>/` | `/en/blog/<slug>/` |
| Fixed page | `/sv/info/<slug>/` | `/en/info/<slug>/` |
| Search | `/sv/sok/` | `/en/search/` |
| Market stall | `/sv/pa-torget/` | `/en/on-the-square/` |

`/` redirects to `/sv/`. Trailing slash always. Swedish is the content
language. English has a complete interface but little content so far (one
solution page, two fixed pages); English lists show what exists.

Category slugs may not use a reserved path (`RESERVED` in `ui.ts`, checked by
`validate.mjs`).

## Rendering details worth knowing

- **Affiliate links:** `affiliateHref()` in `src/lib/content.ts` builds
  `https://www.amazon.se/dp/<ASIN>?tag=electro066-21&…` from `asin`
  (`src/lib/affiliate.ts`). Rendered only by `ProductCard`, `ProductTile` and
  `CompareTable`, always with `rel="sponsored nofollow noopener"` and
  `data-affiliate`.
- **Disclosure:** `AffiliateDisclosure.astro`, placed before the first buy link
  on every page that has one. `isCommercial(products)` decides. The audit fails
  a built page where a buy link comes before it.
- **Photos:** `ProductTile.astro` stacks up to three photos and cross-fades
  them with CSS. The viewer opens with `:target` (no script needed).
- **Filter bar:** `GearFilter.astro` renders the buttons (hidden without
  JavaScript). Groups come from `src/lib/gear-groups.ts`.
- **SEO:** canonical, hreflang, Open Graph, JSON-LD breadcrumbs, articles and
  FAQ (`src/lib/seo.ts`). The sitemap excludes skeletons (`astro.config.mjs`).
- **Search:** Pagefind indexes the built site after `astro build`; the index
  lives in `site/pagefind/`.
- **Version stamp:** `src/lib/build-stamp.ts` — the time of the last commit
  touching `src`, `public`, `astro.config.mjs` or the package files. Shown next
  to the logo (temporary, removed before launch) and always in
  `<meta name="eldebosh-build">`.
- **Asset caching:** `.htaccess` caches JS and CSS for a year. Hashed files in
  `_astro/` are safe; the fixed-path script gets `?v=<content hash>`
  (`src/lib/asset-hash.ts`).

### The one script: `public/js/eldebosh-ui.js`

1. **Filter buttons** above the home-page product grid.
2. **Photo viewer**: no history entries, Escape closes, focus is trapped, and
   each dialog is moved to `<body>` (a tile with `transform` would clip a fixed
   dialog).

Both degrade: without JavaScript the filter bar stays hidden and every product
shows; the viewer still opens through `:target`. Tested in jsdom
(`npm run test:ui`) and in Chromium (`npm run test:browser`).

### Build integrations (`astro.config.mjs`)

| Integration | Does |
|---|---|
| `mdx`, `sitemap` | Standard; the sitemap filter drops skeleton pages |
| `eldebosh-admin-cms` | Copies `node_modules/@sveltia/cms/dist/sveltia-cms.js` into `site/admin/`, and serves it in dev. The file name must stay `sveltia-cms.js`: the CMS starts itself only when its script URL ends with that name |
| `eldebosh-product-tiles` | Composes every upload that is not yet a 720×720 tile into one, in the build output (`scripts/lib/tile.mjs`). The source file is never modified |

A second build mode, `ELDEBOSH_PREVIEW=1`, includes unpublished drafts and
writes to `.preview-site/`; it is used only by `npm run preview:file` and can
never be published (the publish script refuses it).

## Design system

All values are CSS custom properties on `:root` in `src/styles/global.css`.
Never write a literal colour in a rule; `check:colors` refuses colours outside
the palette.

| Token | Value | Use |
|---|---|---|
| `--ink` / `--ink-2` / `--muted` | `#10161D` / `#3F4C59` / `#66727F` | body text / secondary / labels |
| `--paper` / `--page` | `#FFFFFF` / `#E7F2FD` | cards / page background |
| `--mist`, `--mist-2`, `--line`, `--line-2` | light blues | soft surfaces, borders |
| `--brand` | `#1273D1` | links, buttons, active chips |
| `--brand-deep` | `#123F66` | header and footer |
| `--brand-hero` | `#14456E` | hero |
| `--brand-soft` / `--brand-tint` | `#F0F7FE` / `#D3E7FA` | page-head band, tinted surfaces |
| `--volt` / `--volt-deep` | `#55C6F2` / `#2FB2E6` | the accent: charge bar, tested dot, primary button |

Type: `--font-display` (Inter Tight) for headings, `--font-body` (Inter) for
everything else; sizes from the fluid scale `--step--2` … `--step-4`
(`clamp()`), never a fixed `font-size`. Spacing: `--gap`, `--section`; widths
`--wrap` (78rem) and `--wrap-text` (44rem); radii `--r-sm`, `--r`, `--r-lg`.

The motif is the **charge bar** (`.charge`): a grey track filled with `--volt`
to `--fill`. The logo's E is the same motif: three rounded bars, the middle
one sky blue.

Behaviour rules: hover effects only inside `@media (hover: hover)`;
`prefers-reduced-motion` stops animation; touch targets ≥ 44px on coarse
pointers; `:focus-visible` is always drawn.

### Brand assets

`brand/` holds the logo in every variant, icons, social images and print
files; `brand/GUIDELINES.md` is the usage guide. Everything is generated by
`brand/src/` (Python for SVG from the font, Playwright for PNG and PDF):

```
pip install -r brand/src/requirements.txt
npm run brand:all
```

The wordmark is converted to paths from the local Inter Tight font, so it
renders identically everywhere. Output is deterministic except PDF timestamps.
