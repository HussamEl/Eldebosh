## بروتوكول التسليم

### ما يُرسَل ومتى

| الحالة | ما يُرسَل |
|---|---|
| تعديل بصري | **ملف المعاينة وحده** |
| تعديل في المحتوى أو البيانات | لا شيء — يُحدَّث في المستودع |
| نهاية مرحلة | الحزمة الكاملة |
| طلب صريح | ما طُلب |

### قبل أي تسليم

```
npm run verify
```

ستة فحوص متتالية:

| # | الفحص | ماذا يمنع |
|---|---|---|
| ١ | القواعد الملزمة | منتج بلا مصدر · ادعاء تجربة · رابط خام · سعر ثابت · تناقض خط الإنتاج |
| ٢ | البناء | خطأ في الكود أو البيانات |
| ٣ | اختبار الواجهة | جزيرة تفاعلية معطّلة |
| ٤ | فحص الصفحات | روابط مكسورة · عناوين مفقودة · أوصاف SEO |
| ٥ | قائمة الخادم | تحديث `SERVER_FILES.md` |
| ٦ | الحالة والأصول | تحديث `STATE.md` و`ASSETS.md` |

**إن فشل أي واحد، لا تسلّم.**

### ترقيم الإصدارات

| النوع | متى |
|---|---|
| `v1.1` | إضافة محتوى أو منتجات — بلا تغيير بنيوي |
| `v1.5` | ميزة جديدة أو تغيير في التصميم |
| `v2.0` | تغيير معماري أو قرار مغلق يُعاد فتحه |

### عند كل تسليم

١. أضف سطرين في أعلى هذا الملف.
٢. حدّث `STATE.md` — يُحدَّث آلياً في `verify`.
٣. إن اتُّخذ قرار جديد: أضفه في `DECISIONS.md`.
٤. إن ظهرت مشكلة أو حُلّت: حدّث `ISSUES.md`.
٥. إن تغيّر خطر: حدّث `RISKS.md`.
