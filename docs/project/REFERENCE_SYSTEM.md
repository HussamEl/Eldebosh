# نظام المراجع — v1.0

> بدل إعادة رفع الملفات والصور في كل محادثة، **اكتب رمزاً**.
> هذه الوثيقة تشرح النظام وحدوده التقنية بدقة.

---

## 1. المشكلة التي يحلها

في مرحلة التحضير كانت كل صورة تُرفَع مرة، ثم **يُعاد قراءتها مع كل رسالة تالية** في نفس المحادثة. عشر صور في محادثة طويلة تُقرأ مئات المرات.

**النتيجة:** استهلاك يتضخم بلا علاقة بما يُنجَز.

---

## 2. حقيقة تقنية يجب معرفتها

خانة **Context** في مشروع Claude تدعم: `PDF` · `DOCX` · `CSV` · `TXT` · `HTML` · `ODT` · `RTF` · `EPUB` · `JSON` · `XLSX`.

**⚠️ وهي تستخرج النص فقط — عدا ملفات `PDF` متعددة الوسائط.**

**ماذا يعني هذا عملياً:**

| ما تضعه في Context | هل تُرى الصور؟ |
|---|---|
| صورة `PNG` أو `JPG` مباشرة | ❌ **لا** |
| ملف `PDF` يحتوي صوراً | ✅ **نعم** |
| ملف نصي يصف الصور | ✅ النص فقط |

**لهذا لا يكفي إنشاء مجلد صور.** الحل الصحيح ثلاثي.

---

## 3. النظام — ثلاث طبقات

### الطبقة الأولى: الصور في المستودع

الصور تعيش في:

```
public/uploads/
```

وهي جزء من حزمة المشروع. **عند إرسال الحزمة مرة واحدة، تصبح كل الصور متاحة بمساراتها** بلا رفع منفصل.

### الطبقة الثانية: فهرس نصي

```
ASSETS.md
```

جدول يربط كل رمز بمساره ووصفه. **يُولَّد آلياً:**

```
npm run assets
```

هذا الملف يوضع في خانة Context — نص خفيف جداً.

### الطبقة الثالثة: كتالوج بصري

```
ASSETS-CATALOG.pdf
```

كل الصور في صفحة واحدة تحت رموزها. **يوضع في Context أيضاً**، وهو `PDF` فتُرى الصور فعلاً.

---

## 4. الرموز

| البادئة | النوع | مثال |
|---|---|---|
| `P` | منتج | `P-03` |
| `P-NN-K` | صورة منتج | `P-03-2` |
| `B` | أصل هوية | `B-02` |
| `S` | لقطة شاشة | `S-01` |

### تسمية صور المنتجات

```
P-01-1.jpg     الصورة الأولى للمنتج الأول
P-01-2.jpg     الثانية
P-01-3.jpg     الثالثة
```

**من صورة إلى ثلاث لكل منتج.** الرقم الأول رقم المنتج في `produkter.csv`، والثاني ترتيب الصورة.

**الصورة الأولى هي الأساسية** — تظهر وحدها إن لم يكن غيرها، وهي التي يحمل نصها البديل الوصف الكامل.

### التبديل التلقائي

على الموقع، المنتج بأكثر من صورة **تتبدّل صوره تلقائياً** بتلاشٍ متقاطع كل أربع ثوانٍ ونصف.

**بلا JavaScript إطلاقاً** — حركة `CSS` خالصة. وتتوقف عند تمرير المؤشر ليتأمل الزائر، وتتعطّل كلياً لمن يفضّل تقليل الحركة في إعدادات جهازه.

**شارة صغيرة** أعلى البطاقة تعرض عدد الصور.

### الحد الأقصى ثلاث

يفرضه المخطط. الرابعة توقف البناء.

**السبب:** أربع صور لمنتج واحد تُبطئ الشبكة بلا فائدة، والثالثة تكفي: عام، وتفصيل، واستخدام.

---

## 5. كيف تستخدمه

**بدل** إرفاق صورة وكتابة "هذه البطاقة فيها مشكلة"، اكتب:

```
P-03 الصورة مائلة
```

```
B-02 الشعار صغير على الجوال
```

```
S-01 هذا ما أراه في القائمة
```

**ولإرسال لقطة جديدة:** أرسلها **مرة واحدة** واطلب حفظها برمز. تُحفظ في `assets/screens/` وتُضاف إلى الفهرس، فلا تُرسل مرة أخرى أبداً.

---

## 6. المبدأ العام — ينطبق على كل شيء

**كل ما يُراجَع أكثر من مرة يُخزَّن في ملف مرجعي بدل المحادثة.**

| بدل مراجعة المحادثة عن | اقرأ |
|---|---|
| القواعد والدور | `PROJECT_INSTRUCTIONS` |
| الحالة والقرارات وأسبابها | `PROJECT_CONTEXT` |
| الصور والأصول | `ASSETS.md` + `ASSETS-CATALOG.pdf` |
| بنية الكود والأوامر | `HANDOFF.md` |
| المشاكل القائمة وأدلتها | `DEPLOY_FIX.md` · `REMOVE_WORDPRESS.md` |
| خريطة المحتوى | `KEYWORD_MAP.md` |
| قواعد التصوير والتجربة | `HANDS_ON_GUIDE.md` |
| ملفات الخادم | `SERVER_FILES.md` |

**القاعدة:** إن احتجت معلومة من محادثة سابقة، فهي **ناقصة من الوثائق** — أضفها فوراً بدل البحث عنها مرة أخرى.

---

## 7. ما يوضع في Context

| الملف | لماذا |
|---|---|
| `PROJECT_CONTEXT_v1.0.md` | الحالة والقرارات |
| `ASSETS.md` | فهرس الرموز — نص خفيف |
| `ASSETS-CATALOG.pdf` | الصور مرئية بالرموز |

**ولا شيء غيرها.** بقية الوثائق داخل حزمة المشروع، تُقرأ عند الحاجة.

---

## 8. التحديث

بعد إضافة أي صورة منتج جديدة:

```
npm run assets
```

يُعاد توليد الفهرس. **والكتالوج البصري يُطلب توليده** حين تتغير الصور.

---

## 9. الأثر المتوقع

| الحالة | التكلفة |
|---|---|
| صورة مرفقة في محادثة طويلة | تُقرأ مع كل رسالة |
| نفس الصورة عبر رمز في Context | تُقرأ مرة عند بدء المحادثة |

**والأهم:** المحادثة تبقى قصيرة، والقصر هو ما يخفض التكلفة فعلاً.
