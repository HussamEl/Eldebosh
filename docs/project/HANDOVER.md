## 1. ما هو المشروع

`eldebosh.com` — موقع سويدي عن الشحن والكابلات والحوامل. نموذج الدخل: روابط
شراكة أمازون (`amazon.se`، الوسم `electro066-21`، الحساب مقبول وعامل).

**الميزة التي يقوم عليها كله:** صاحب المشروع **يملك المنتجات فعلاً** ويصوّرها
بنفسه. فلا صور من المتجر، ولا «أفضل في الاختبار»، ولا رقم بلا مصدر.

**اللغات:** السويدية هي لغة المحتوى، والإنجليزية واجهة كاملة بمحتوى غير مترجم
بعد.

## 2. أين وصلنا

**لا تقرأ رقماً من هنا. شغّل:**

```
npm run state
```

يطبع الحالة كاملة ويحدّث `docs/project/STATE.md`. **هو المصدر الوحيد للأرقام**
في هذا المشروع، وأي رقم مكتوب بيد في أي وثيقة يُعامَل كخطأ لا كمصدر.

**والثابت الذي لا تغيّره الأرقام:**

- **الموجة الأولى — عنقود البطارية — مكتملة.** أول عنقود يُغلق.
- **الفئتان مفعّلتان**، والنصوص القانونية والمعرِّفة الستّ مكتوبة ومنشورة.
- **الاختناق واحد:** مصدر المواصفة. الترشيح لا يكون إلا من منتج `verified`،
  والدليل لا يُنشر بأقل من ترشيحين. فكل دليل مغلق مغلقٌ على هذا وحده.
- **وأول باب انفتح:** `kablar` فيها كابلان موثّقان — دليل الكابلات لم يعد
  محجوزاً على البيانات، بقي نصّه.

**حقلان لا يُخلطان:** `published` يقول «هل الرابط موجود؟» و`stage` يقول «إلى
أين وصل النصّ؟». فالهيكل المعلَن هو `published: true` مع `stage: draft`: رابطٌ
حيّ يقول للزائر إنه لم يُنشر فيه شيء بعد ويدعوه للكتابة. **قرارُ مالك، لا سهو.**

**الاختناق الوحيد اليوم:** مصدر المواصفة. الترشيح لا يكون إلا من منتج
`verified`، والدليل لا يُنشر بأقل من ترشيحين.

**وأول باب انفتح:** `kablar` فيها كابلان موثّقان، فدليل الكابلات لم يعد محجوزاً
على البيانات — بقي نصّه. التفصيل في `TASKS.md`.

## 3. المستودع

`github.com/HussamEl/Eldebosh` — عام.

| المسار | ماذا فيه |
|---|---|
| `src/content/` | الصفحات `MDX`: حلول · أدلة · مقارنات · مقالات · صفحات ثابتة |
| `src/data/products/sv/` | **المنتجات — ملف `YAML` لكل منتج.** هذه هي قاعدة البيانات |
| `src/data/categories/` | الفئات والفئات الفرعية |
| `src/components/` · `src/pages/` | قوالب `Astro` |
| `src/styles/global.css` | **كل الأنماط في ملف واحد** — لا `CSS` داخل المكوّنات |
| `scripts/` | الفحوص والمولّدات — كلها `node`، وواحد `python` |
| `docs/project/` | الوثائق الحاكمة والسجل والمسائل |
| `public/admin/` | لوحة التحرير `Sveltia CMS` |
| `site/` | **مخرَج البناء، مدفوع في المستودع عن قصد** |

### الفروع

```
main     المصدر + site/     ← كل العمل هنا
deploy   محتويات site/ في الجذر  ← تسحب الاستضافة منه
```

### النشر — تلقائي بالكامل

```
دفعة إلى main → GitHub Actions يبني ويفحص → يحدّث فرع deploy
              → Webhook يوقظ الاستضافة → تسحب إلى public_html
```

**لا `FTP` ولا أسرار ولا خطوة يدوية.** والاستضافة `Hostinger`. السبب أنّ
الاتجاه معكوس: خوادم غيتهب محجوبة عن الدخول، فالاستضافة هي التي تخرج وتأخذ.

**وكيف تتأكد أن النشر جرى:** بجانب زر الهوم على الموقع **ختمُ بناء** يساوي وقت
البناء. ساواه ← النشر تمّ. (وهو أداة مؤقتة تُحذف قبل الإطلاق — `T7`.)

## 4. كيف تشتغل عليه

```bash
npm ci
npm run dev        # خادم محلي
npm run verify     # البوابة — أربعة عشر فحصاً
```

**`npm run verify` هو المعيار الوحيد.** لا يُدفع شيء وهو أحمر، ولا تُعدّ مهمة
منجزة وهو أحمر. وفي غيتهب يُضاف إليه فحص خامس عشر: `check:drift`.

### ما تفحصه البوابة، ولماذا بُني كل واحد

| الفحص | يمنع |
|---|---|
| `validate.mjs` | القواعد الملزمة كلها — سبع عشرة كتلة قواعد، كل واحدة من عطب وقع فعلاً |
| `test:claims` | ٣٢ حالة اختبار لقاعدة الادعاء — نصٌّ يدّعي تجربة أو عدداً بلا بيانات تسنده |
| `check:css` | قاعدة `CSS` مكررة أو رمز لون غير معرَّف |
| `check:colors` | لون خارج نظام التصميم |
| `check:docs` | رقم رسالة أو إصدار وثيقة غير متّسق |
| `check:admin` | **حقل موجود في الملفات ولا تعرفه لوحة التحرير** — أول حفظ منها كان يمحوه |
| `check:drafts` | صفحة منشورة ونصّها مسودّة — **يُسقط البناء** |
| `audit` · `test:browser` | صفحة بلا `h1` أو وصف · أعطاب تظهر في متصفح حقيقي |
| `check:drift` (في غيتهب) | `site/` لا يطابق بناءً نظيفاً من المصدر |

**ولا يُضاف فحص إلا بعد عطب وقع.** كل واحد منها مكتوب في رأسه: أيّ عطب أنتجه.

## 4b. ضجيج معروف — لا تُبلّغ عنه ولا تسأل حسام فيه

**ثلاثة أشياء ستراها في أول ساعة، وكلّها متوقَّعة ومحسومة.** حُصرت هنا لأن
جلسةً جديدة اصطدمت بها في `2026-09-04` فرفعتها إلى حسام كقرارات — وليست
قرارات (`I-022`).

### ١. `verify` يجعل الشجرة «متّسخة» في كل مرة

بعد أي `npm run verify` — **ولو لم تحرّر حرفاً** — تجد عشرات الملفات معدّلة،
سطراً واحداً في كلٍّ منها: **ختم البناء**، أي `<meta name="eldebosh-build">`
وما يوافقه في الرأس. البناء يكتب فيه وقته فيتغيّر الوقت. **لا محتوى ولا مواصفة
ولا صفحة.**

**والضجيج محصور في ثلاثة مواضع بالضبط، لا أكثر:**

```
site/
docs/project/STATE.md
docs/project/SERVER_FILES.md
```

**فالتراجع يكون مُوجَّهاً إليها وحدها:**

```
git restore site/ docs/project/STATE.md docs/project/SERVER_FILES.md
```

> **⚠️ ولا تكتب `git restore .` أبداً.** يمحو **كل** تعديل غير مودَع، بما فيه
> عملك أنت. وهذا ليس تحذيراً نظرياً: كتبتُ هذا القسم أول مرة ثم شغّلتُ
> `git restore .` لأختبره، **فمحوتُ الوثائق التي كنتُ أكتبها للتوّ** — سبعة
> ملفات لم تكن مودَعة. أُعيدت كتابتها، وبقيت الجملة هنا بثمنها.

**ولا تُودِع الضجيج ولا تدفعه ولا تسأل حسام عنه.** دفعةٌ بسبعين ملفاً من أجل
تغيّر وقت تُشعل خط النشر كاملاً وتلوّث السجل.

*(ولماذا لا يكسر هذا البوابة على غيتهب: `check:drift` **يقنّع الختم** فلا
يحسبه انحرافاً. والختم مجدوَل للحذف قبل الإطلاق — `TASKS` مهمة `T7`.)*

### ٢. سبعة تنبيهات في `npm run check` — كلها معروفة ومسجّلة

**التنبيه ليس خطأً.** البوابة خضراء وفيها هذه السبعة:

| العدد | التنبيه | الحالة |
|---|---|---|
| ٥ | مصدر المواصفة صفحة أمازون لا صفحة مصنّع | **مفتوح ومقصود** — المسألة `I-019`، وهي العمل الجاري |
| ٢ | نصّ التجربة مكرّر بين `P-01` و`P-04` و`P-11` | **قرار حسام `2026-09-04`: يُترك.** سيعيد كتابة النصوص بنفسه، وهو وحده من يملك ذلك |

**فلا تُعِد رفع أيٍّ منها كاكتشاف.** إن أردت العمل على الأولى فاقرأ `I-019`.

### ٣. الفرع الذي تدفع إليه

**اتبع الفرع الذي تعطيك إياه بيئة تشغيلك.** إن فرضت فرعاً باسمها فهو الصحيح،
ولا تسأل حسام فيه. وإن لم تفرض شيئاً فالعمل على `main`.

**ولا `Pull Request`** إلا إن طلبه حسام صراحةً.

## 5. القواعد التي تحكم العمل

في `docs/project/`، وتُقرأ بهذا الترتيب:

| الملف | ما فيه |
|---|---|

| `CONTEXT.md` | الحالة والقرارات وأسبابها |

| `ISSUES.md` | كل عطب وقع، وكيف عولج، وأيّ حارس بُني بعده |
| `LOG.md` | سجل المراسلات المرقّمة بين الأطراف |
| `STATE.md` | لوحة الأرقام — **مولّدة، لا تُحرَّر يدوياً** |
| `PHOTO_NAMING.md` | تسمية الصور ومعالجتها |

### أربع قواعد تُكسر أكثر من غيرها

1. **لا رقم ولا مواصفة بلا مصدر.** والمصدر إمّا صفحة مصنّع، **أو صورةٌ من
   تصويرنا تُظهر المطبوع على الجهاز** (`spec_photo`). صفحة بائع لا تكفي.
2. **صور أمازون وأسعارها ممنوعة** حتى تُفتح الواجهة البرمجية بعد ثلاث مبيعات
   مؤهَّلة.
3. **رابط الشراكة يُبنى من `asin` وحده.** لصق رابط أمازون يدوياً يرفضه الفحص.
4. **`published` و`stage` حقلان مستقلان:** الأول «هل الرابط موجود؟»، والثاني
   «إلى أين وصل النصّ؟». والنصّ لا يظهر إلا عند `stage: published`.

## 6. الأطراف وآلية التواصل

ثلاثة أطراف لا يتصل بعضها ببعض. **حسام هو القناة الوحيدة** — ينسخ ويلصق.

| الطرف | يفعل | لا يفعل |
|---|---|---|
| **حسام** | يملك · يقرّر · يصوّر · ينقل الرسائل | لا يبرمج |
| **Claude Project** | المواصفات · المحتوى · `SEO` · التحرير | **لا يدفع إلى غيتهب إطلاقاً** |
| **Claude Code** | المستودع · التنفيذ · الفحوص · النشر | لا يقرّر تحريراً |
| **Gemini** | بحث خارجي عند الطلب | — |

### الترقيم — إلزامي

كل رسالة تفتح بسطر واحد:

```
EB-062 · Claude Code · 2026-09-04 13:25 · رداً على EB-061
```

عدّاد **واحد لكل الأطراف**، وتوقيت **كارلستاد** يُقرأ من الساعة لا يُقدَّر.
والرقم التالي يطبعه `npm run check:docs`. والسجل في `LOG.md` يفصل أي خلاف.

### وكل رد يُختم بلوحة الأطراف

```
| | الطرف | الحالة |
|---|---|---|
| ✍️ | كلاودي كود | كتب هذا الرد · EB-062 |
| 🔴 | كلاودي بروجيكت | مطلوب: <إجراء واحد> |
| 💤 | جيميناي | لا شيء ينتظره |
| ✅ | حسام | لا شيء مطلوب |
```

`✍️` كتب · `⏳` ينتظر · `🔴` عليه عمل الآن · `🟡` يمكن أن ينتظر · `💤` غير معنيّ
· `✅` أنجز.

**كل طرف يظهر في كل مرة** — غيابُ طرف من اللوحة هو ما أضاع الخيط سابقاً.

### الخلل المعروف في الآلية

**رسائل تضيع.** `Claude Project` يكتب في محادثته ولا يملك وسيلة دفع، فما لا

وصفحة كاملة، فظهرت فجوة في ترقيم المنتجات كشفت المشكلة.

**والعلاج المطبَّق:** كل ما يصل يُودَع في المستودع في الدفعة نفسها، ويُسجَّل في
`LOG.md`. المستودع هو الذاكرة الوحيدة المشتركة — لا محادثة.

## 8. البدء من محادثة جديدة

**العدّاد صُفِّر في `2026-09-04`.** أول رسالة في أي محادثة جديدة رقمها `EB-001`.
والأرشيف السابق محفوظ في `LOG.md` تحت عنوان «أرشيف»، ولا يُستشهد برقم منه.

**ما يُلصق في كل محادثة:**

| الطرف | يُعطى |
|---|---|
| **Claude Project** | `INSTRUCTIONS.md` + `CONTEXT.md` + `BRIEFING.md` — النصّ كاملاً |
| **Claude Code** (محادثة جديدة) | لا شيء يُلصق. يقرأ المستودع، ويبدأ من هذه الصفحة |
| **Gemini** | `BRIEFING.md` وحدها، ثم السؤال البحثي |

**وأول ما يفعله `Claude Code` في محادثة جديدة:**

```
npm ci
npm run verify
git restore site/ docs/project/STATE.md docs/project/SERVER_FILES.md
npm run check:docs
```

`verify` يجب أن يكون أخضر قبل أي تعديل · السطر الثالث يمسح ختم البناء وحده
(**ولا تكتب `git restore .`** — القسم `4b`) · `check:docs` يطبع رقم رسالتك
والوقت الصحيح.

**والفرع:** اتبع ما تعطيك إياه بيئتك ولا تسأل حسام فيه. **واقرأ القسم `4b` قبل
أن ترفع إليه أي ملاحظة** — أغلب ما يبدو مفاجئاً في الساعة الأولى مذكور هناك.

**ثم يعلن في أول رد:** رقم الرسالة، وإصدارات الوثائق الثلاث، وسطر الحالة من
`STATE.md`. ثلاثة أسطر تُغني عن مئة رسالة سابقة.
