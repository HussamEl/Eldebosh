## ما نعرفه يقيناً

| الدليل | ما يعنيه |
|---|---|
| البناء ينجح دائماً | المشكلة ليست في الكود |
| المحاولتان تنتهيان بـ`2m 0s` بالضبط | المهلة كاملة — الاتصال لم يُفتح أصلاً |
| `Timeout (control socket)` | لم يصل إلى مرحلة كلمة المرور |
| نجح مرة واحدة ثم توقف | نمط حجب تلقائي للعنوان |

**الاستنتاج:** خادم Hostinger لا يستجيب لخوادم GitHub. لا يوجد إعداد في المشروع يعالج هذا.

## الخطوة الأولى: اجمع الدليل

أضفت أداة تشخيص إلى المستودع. **لا تنشر شيئاً** — تفحص الاتصال فقط.

من صفحة المستودع على GitHub:

```
Actions ← Diagnose FTP connection ← Run workflow
```

تنتظر دقيقتين، ثم تفتح النتيجة.

### ماذا تفحص

- عنوان خادم GitHub الذي يحاول الاتصال
- هل يُترجم اسم خادمك؟
- هل المنافذ `21` و`990` و`22` مفتوحة أم محجوبة؟
- رد الخادم الخام على المنفذ `21`
- محاولة دخول مشفّرة كاملة
- هل يدعم الخادم `SFTP`؟

### كيف تقرأ النتيجة

**إن كان المنفذ `21` مغلقاً:** الحجب مؤكد. انتقل إلى الخطوة الثانية.

**إن كان مفتوحاً وفشل الدخول:** المشكلة في الاعتماد، لا الحجب. أعد ضبط الأسرار الأربعة.

**إن كان المنفذ `22` مفتوحاً:** الخادم يدعم `SFTP`، وهو حل أفضل وأكثر استقراراً. أخبرني وأحوّل ملف النشر.

## الخطوة الثانية: راسل الدعم

انسخ نتيجة التشخيص كاملة، وأرسلها مع هذا النص:

```
My GitHub Actions deployment cannot connect to FTP.
Error: Timeout (control socket) on port 21.
It worked once, then stopped permanently.

Diagnostic output attached.

1. Do you block GitHub Actions IP ranges on your firewall?
2. Can you whitelist them for my account?
3. Does my plan support SSH/SFTP instead of FTP?
4. Is there any rate limit that blocks repeated connections?
```

**السؤال الثالث هو الأهم.** إن كان الجواب نعم، فالمشكلة تُحلّ في عشر دقائق.

## الخطوة الثالثة: إن لم يحلّوها

### الخيار الأول: SFTP

أكثر استقراراً ولا يُحجب عادةً. يحتاج مفتاحاً بدل كلمة مرور.

### الخيار الثاني: منصة نشر مخصصة

الموقع ثابت بالكامل، وهذا يجعله مثالياً لمنصة مثل Cloudflare Pages أو Netlify.

**كيف تعمل:** تربط المستودع مرة واحدة، فكل رفع يبني وينشر خلال ثلاثين ثانية. بلا FTP وبلا أسرار وبلا حجب.

**والموقع يصبح أسرع** لأنه يُخدَّم من شبكة عالمية بدل خادم واحد.

**الدومين يبقى ملكك** — تغيّر إعداد DNS فقط.

**التكلفة: صفر** على الخطة المجانية.

**الثمن:** خدمة إضافية تديرها، واستضافة Hostinger تبقى مدفوعة بلا استعمال.

### الخيار الثالث: الرفع اليدوي

ما تفعله الآن. يعمل، لكنه يعطّل لوحة التحرير — لأن اللوحة تكتب في GitHub، وبلا نشر تلقائي لا يصل ما تكتبه إلى الموقع.

## تحسين مهم في ملف النشر

أضفت خياراً يجعل النشر **يحذف من الخادم ما لم يعد موجوداً في المشروع**.

**السبب:** الرفع كان يستبدل الموجود ويترك القديم، فتبقى صفحات محذوفة تعمل بتصميمها القديم. هذا سبب كل الارتباك الذي حدث.

هذا يعمل تلقائياً حالما يعود الاتصال.
