# كيف يُضاف منتج — الدليل الكامل

> **الإصدار `v1.0`.** هذه الوثيقة كانت ناقصة حتى `2026-09-20`: المعرفة كانت
> موزّعة على `CLAUDE.md` و`INSTRUCTIONS` و`validate.mjs` و`PHOTO_NAMING` وإعدادات
> لوحة التحرير، ولا مكان واحد يجمعها. فمن أراد إضافة منتج قرأ خمسة ملفات أو أخطأ.
>
> **من يقرأ هذه الوثيقة:** أي طرف يُطلب منه إعداد منتج جديد.

---

## 0. الحقيقة التي تحسم كل ما بعدها

**طرف واحد فقط يستطيع أن يكتب في المستودع: `Claude Code`.**

| الطرف | ماذا يفعل عند إضافة منتج |
|---|---|
| **حسام** | يملك المنتج · يصوّره · يعطي `ASIN` · يرفع الصور من `/admin/` |
| **Claude Code** | يكتب ملف `YAML` ويدفعه · يشغّل الفحص |
| **Claude Project** | يكتب النصوص السويدية: `pros` · `cons` · `best_for` · المواصفات من مصدر |
| **طرف إضافي** | بحث خارجي عن مصدر مواصفة، إن طُلب |

**فمن ليس `Claude Code` لا «يضيف» منتجاً — بل يُنتج نصّاً جاهزاً للّصق.** وهذا نافع
جداً، لكن تسميته إضافةً تَعِد بما لا يُنجَز.

**والصورة لا تعبر المحادثة.** ترفقها في محادثة ← تبقى في المحادثة. طريقان لا ثالث:

```
١. ترفعها أنت من /admin/   ← لوحة التحرير تدفعها إلى غيتهب
٢. تعطيها لـClaude Code    ← يضعها في public/uploads/ ويدفع
```

## 1. قبل أن تكتب حرفاً — أربعة أرقام تُقرأ ولا تُخمَّن

```
npm run state
```

يطبع كل شيء ويحدّث `STATE.md`. ومنه تأخذ:

| ما تحتاجه | من أين |
|---|---|
| **الرمز الحرّ التالي** `P-NN` | أعلى رمز مستعمل + ١ |
| الفئات والفئات الفرعية المتاحة | `src/data/categories/*.yaml` |
| هل المنتج موجود أصلاً؟ | قائمة المنتجات |

**الرمز `P-NN` يُسنَد مرة واحدة ولا يتغيّر أبداً** — أسماء الصور مبنية عليه، وتغييره
يفصل المنتج عن صوره. والفحص يرفض رمزاً مكرراً منذ `2026-09-20`.

---

## 2. الفئات — اكتبها كما هي حرفياً

**الفئتان المفعّلتان وفئاتهما الفرعية:**

```
laddning-och-strom
    powerbanks · snabbladdare · kablar · billaddning

hallare-och-ordning
    bilhallare · skrivbordsstall · kabelordning
```

**حرف ناقص واحد يُسقط البناء الآن** — وقبل `2026-09-20` كان يمرّ صامتاً فيختفي
المنتج من كل أزرار التصفية ومن صفحة فئته. الفحص يقترح عليك الاسم الصحيح.

**وأزرار التصفية في الصفحة الرئيسية ليست هي الفئات الفرعية.** تجميعها معرَّف في
`src/lib/gear-groups.ts` وحده (`D-030`): زر `Laddare` يجمع `snabbladdare`
و`billaddning`، وما لا مجموعة له يظهر تحت `Alla` فقط.

## 3. الملف — أين يوضع وبماذا يُملأ

```
src/data/products/sv/<id>.yaml
```

و`<id>` حروف صغيرة وأرقام وشرطات فقط، ويصف المنتج لا يسوّقه:
`ugreen-usb-c-kabel-240w-display`.

### الحقول الإلزامية

| الحقل | القاعدة |
|---|---|
| `id` | فريد · `^[a-z0-9-]+$` |
| `code` | `P-NN` · فريد · **لا يتغيّر** |
| `lang` | `sv` |
| `name` · `brand` | كما هما على المنتج |
| `category` · `subcategory` | من القائمة أعلاه حرفياً |
| `price_band` | `budget` · `mid` · `premium` — **ولا حقل `price` أبداً** |
| `owned` · `tested` | انظر القسم ٥ |
| `verified` | `false` حتى يكتمل التوثيق — انظر القسم ٤ |

### الحقول التي تُترك فارغة حتى يكتبها `Claude Project`

```yaml
pros: []
cons: []
best_for: ""
```

**لا تخترعها.** `INSTRUCTIONS` ٦٫١ — ولا رقم ولا مواصفة بلا مصدر.

---

## 4. `verified` — الحارس الذي يقرّر هل يظهر المنتج أصلاً

**`verified: false` ⇐ المنتج لا يظهر في أي صفحة.** وهذا هو الوضع الافتراضي وهو صحيح.

**ولقلبه إلى `true` تحتاج ثلاثة:**

```yaml
verified: true
source_url: "…"          # مصدر المواصفة
last_verified: 2026-09-20
```

**ومصدر المواصفة مقبول من ثلاثة طرق، لا رابعَ لها (`I-019`):**

| الطريق | ما هو | من يأتي به |
|---|---|---|
| **أ** | `source_url` على **صفحة المصنّع** | `Claude Project` |
| **ب** | `spec_photo` — صورتنا للمطبوع على الجهاز | حسام، صورة واحدة |
| **ج** | `owner_checked` — حسام فتح صفحة البائع وقارنها بالجهاز بيده، بتاريخ | حسام |

**وعنوان إعلان على أمازون ليس مصدراً.** يكتبه البائع لا المصنّع. والفحص يطلق تنبيهاً
إن كان `source_url` صفحة بائع بلا (ب) أو (ج).

**و`spec_photo` يجب أن تكون واحدة من `own_photos` نفسها** — وإلا فهي ادعاء بلا ملف.

---

## 5. `owned` و`tested` — ثلاث حالات لا رابع لها

| الحالة | ما يُسمح | ما يراه القارئ |
|---|---|---|
| `tested: true` | صيغة التجربة · صورنا · ملاحظات الاستخدام | وسم: نملكها ونستعملها |
| `owned: true` فقط | صورنا ووصف مادي — **بلا حكم على الأداء** | نملكها، والبيانات تُستكمل |
| كلاهما `false` | مواصفات موثقة ومصادر منشورة | سطر صريح: لم نجرّبها |

### `tested: true` يفرض خمسة حقول — والبناء يسقط بدونها

```yaml
tested: true
owned: true              # لا يجوز ادعاء استخدام ما لا نملك
owned_since: 2026-03-01
usage_period: "6 månader"
own_photos: [ … ]        # صورة واحدة على الأقل من تصويرنا
hands_on: [ … ]
hands_on_limits: [ … ]   # ⚠️ الأهم
```

**و`hands_on_limits` هو أهمها:** أن تقول ما لا تُظهره تجربتك هو ما يفصلنا عن منافس
يدّعي اختباراً لم يجرِ. لا تتركه شكلياً.

**وممنوع دائماً:** `Bäst i test` · ادعاء قياس بجهاز · نسخ نصّ المصدر حرفياً.
والفحص الآلي يرفض أي عبارة تجربة لا يقابلها منتج `tested: true`.

## 6. الصور

### التسمية — الصيغة الفعلية في المستودع

```
P-NN-K.webp                 الشكل الأساسي
P-NN-K-<ASIN>.webp          حين يُعرف الـASIN وقت الرفع
P-NN-K-v2.webp              حين تُستبدل صورة بأخرى
```

`NN` رقم المنتج · `K` رقم الصورة `1..3`. **الصيغة `webp` حصراً، مربعة ٧٢٠ بكسل.**

### ماذا تصوّر

| الصورة | ماذا تُظهر |
|---|---|
| `1` | المنتج وحده — **إلزامية** |
| `2` | المقياس — بجانب بطاقة أو هاتف |
| `3` | قيد الاستخدام — **الأقوى تجارياً، ولا يستطيع منافس تزييفها** |

### القواعد الصارمة

- **صور المتاجر وأمازون ممنوعة** حتى تُفتح الواجهة البرمجية بعد ثلاث مبيعات مؤهَّلة.
- **وممنوع تعديلها للتحايل** — التعديل يضاعف المخالفة ولا ينشئ ملكية (`D-021`).
- **وممنوع عرض صورة منتج تحت اسم منتج آخر ولو للاختبار.** الصورة ادعاء بصري.
- **الموضع:** `public/uploads/` · **والمسار في الملف:** `/uploads/…`
- **والفحص يرفض منذ `2026-09-20` صورةً مذكورة بلا ملف على القرص.**

```yaml
own_photos:
  - src: "/uploads/P-24-1.webp"
    alt: "نص بديل بالسويدية يصف ما في الصورة"
    caption: "Vår egen bild."
```

`alt` **بالسويدية** ويصف ما يُرى. والموقع يبدّل الصور بالـ`CSS` وحده — لا جزيرة
`JavaScript` جديدة.

## 7. `ASIN` ورابط الشراء

```yaml
asin: "B0XXXXXXXX"
```

**عشر خانات، حروف كبيرة وأرقام.** والنظام يبني الرابط بالوسم الصحيح وحده.

**وممنوع لصق رابط أمازون يدوياً** — الفحص يرفضه. الوسم `electro066-21` معرَّف في
`src/lib/affiliate.ts` ولا يُكتب في أي ملف منتج.

**وبلا `ASIN` لا زرّ شراء، ولا يدخل المنتج أي دليل.** تظهر البطاقة بعبارة «الرابط قادم».

## 8. ماذا يتغيّر تلقائياً بعد الإضافة — ولا تلمسه بيدك

| يتحدّث وحده | بأي أمر |
|---|---|
| `STATE.md` — الأعداد | `npm run state` |
| `ASSETS.md` — فهرس الصور | `npm run assets` |
| `csv/` — جداول المنتجات | `npm run csv` |
| أعداد أزرار التصفية | تُحسب من الشبكة عند البناء |
| `site/` — الموقع المبني | `npm run build` |

**ولا تكتب رقماً بيدك في أي وثيقة.** هذا هو العيب الذي حُذفت من أجله كل الأرقام
اليدوية في `D-029`.

## 9. ما يحتاج قراراً بشرياً بعد الإضافة

| السؤال | من يقرّر |
|---|---|
| هل يدخل دليلاً أو مقارنة؟ | `Claude Project` — ويلزم ترشيحان على الأقل |
| هل `tested: true`؟ | **حسام وحده** — ادعاء عن شيء استعمله هو |
| أي `problems_solved` يربط بها؟ | `Claude Project` — ويجب أن تكون صفحة حلّ موجودة |
| هل تُفعَّل فئة جديدة؟ | لا فئة في القائمة قبل ٣ صفحات منشورة فيها |

## 10. الخطوات بالترتيب — نسخة عملية

```
١. npm run state              اقرأ الرمز الحرّ التالي
٢. ارفع الصور                 public/uploads/P-NN-K.webp
٣. اكتب الملف                 src/data/products/sv/<id>.yaml
٤. npm run check              القواعد الملزمة — يجب أن يمرّ
٥. npm run verify             البوابة كاملة — يجب أن تكون خضراء
٦. ادفع إلى main              وانتظر الفحص على غيتهب
```

**ولا يُعدّ العمل منجزاً و`verify` أحمر.** ولا يُلتفّ على فحص — يُصلَح سببه.

## 11. الأخطاء التي وقعت فعلاً — اقرأها قبل أن تكررها

| العطب | ما حدث | المرجع |
|---|---|---|
| `ASIN` لطراز آخر | زرّ الشراء كان يبيع طرازاً غير الذي تصفه الصفحة | `I-023` |
| مصدر من صفحة بائع | عنوان الإعلان ليس مواصفة مصنّع | `I-019` |
| رقم مكتوب بيد في وثيقة | تقادم في ساعتين فصار في المشروع مصدران للرقم | `D-029` |
| صورة بمسار ثابت بلا بصمة | وصلت صفحة جديدة وأصل قديم إلى الزائر | `I-025` |
